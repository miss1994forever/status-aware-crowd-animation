# IE-02 精确接入说明（供空间线串行审查）

这是基于只读reference的局部修改说明，不是授权自动合入或整文件替换。尚未接入Unity。当前空间线已有后续修改（至少LowerBodyPolicy默认值已由1改2），必须以其最新工作副本重审。

## 文件与开关

只需三个独立源文件：ExpressionMath.cs、ExpressionPolicy.cs、ExpressionOverlay.cs，命名空间IndividualExpressionCandidate。不要复制reference，不要把tests、build_review.py或HTML放入Unity。复制与编译只能由空间线在停止运行后完成。

在SprintActor字段区增加（保留全部原字段）：

```csharp
public bool UseIndividualExpressionCandidate = false;
public float ExpressionRootSpeed; // 真实根水平速度，m/s
public float ExpressionRightArmAngle, ExpressionRequestedLowering;
readonly IndividualExpressionCandidate.ExpressionPolicy expressionPolicy = new IndividualExpressionCandidate.ExpressionPolicy();
readonly IndividualExpressionCandidate.ExpressionOverlay expressionOverlay = new IndividualExpressionCandidate.ExpressionOverlay();
Transform rightForearm;
```

在Start现有骨骼获取后新增 `rightForearm=B(HumanBodyBones.RightLowerArm);`。不把它加进全局停用检查以免关闭候选时影响旧版；候选单独缺骨应退回旧规则并记录。

真实速度接入：reference SprintDirector.Update第一段同帧位置/速度快照中，在 `velocities[i]=...` 之后增加：

```csharp
Vector3 expressionVelocity=velocities[i]; expressionVelocity.y=0;
actors[i].ExpressionRootSpeed=expressionVelocity.magnitude;
```

不能用期望输入/目标速度/被表达修改的髋位移替代。该行与导航计算无写依赖，但仍需审查新增观察反馈。

## 第一轮：只接上臂，不改腿

在SprintActor.Apply的`float contraction=...;float response=...;`之后生成一次命令：

```csharp
bool candidateEnabled=UseIndividualExpressionCandidate && Mode!=0 && response==0 && rightForearm;
var expressionCommand=expressionPolicy.Step(OwnStatus,
    IndividualExpressionCandidate.ExpressionProfile.SourceToCompact,
    initialHeight,ExpressionRootSpeed,Time.deltaTime,candidateEnabled);
ExpressionRequestedLowering=(float)expressionCommand.RequestedLowering;
ExpressionRightArmAngle=0;
```

`initialHeight`沿用reference已有的固定头到平均脚尺度；不是标准身高。先核实当前角色缩放与EMM单位为米；非均匀缩放不支持。只有有效模式才更新策略，关闭模式Step会Reset。reference的response是附加姿态回应强度；本候选没有复制它的8°夹臂，所以response非零先退回旧分支，不悄悄叠加。

保留原`AppliedLowering=...`和腿IK分支。第一轮由宿主固定LowerBodyPolicy=0以隔离手臂；后续若比较已有高度策略，三条件必须保持完全相同策略和配置。IE-02的RequestedLowering此时仅遥测，不驱动髋部。

用下列局部结构包住reference从`Vector3 inward=...`到`leftArm.rotation=...`这一个上臂块；不能移动或覆盖前面的腿IK块和后面的头部/观测块：

```csharp
Vector3 inward=(rightArm.position-leftArm.position).normalized;
bool appliedCandidate=false;
if(candidateEnabled && expressionCommand.Valid) {
    var edit=expressionOverlay.Apply(hips,head,leftArm,leftForearm,
        rightArm,rightForearm,expressionCommand,true);
    appliedCandidate=edit.ValidFrame;
    if(appliedCandidate) {
        AppliedArmAngle=edit.LeftDegrees; // 新版含义：实际左臂修正角，非原12*c
        ExpressionRightArmAngle=edit.RightDegrees;
    }
}
if(!appliedCandidate) {
    // 原上臂块保持原样，但inward已在外层声明，不要再次声明。
    Vector3 down=(hips.position-head.position).normalized;
    Vector3 axis=Vector3.Cross(inward,-down).normalized,v=leftForearm.position-leftArm.position;
    Quaternion qa=Quaternion.AngleAxis(AppliedArmAngle,axis),qb=Quaternion.AngleAxis(-AppliedArmAngle,axis);
    leftArm.rotation=(Vector3.Dot(qa*v,inward)>Vector3.Dot(qb*v,inward)?qa:qb)*leftArm.rotation;
}
```

关候选应得到原有路径；Mode=0仍是零表达。无效骨架/命令时退回旧规则，宿主需要单独记录fallback，避免把没运行候选算成完成。候选返回ValidFrame也可能因为姿态门控而零修改，必须区分这一正常情况。

## 第二轮：高度通道须单独审查

不要在上轮同时改高度。空间线认可上臂后，保留当前腿策略；若接新高度命令，在原AppliedLowering赋值之后、首次移动hips之前，将候选分支的降低量改为 `expressionCommand.BoundedLowering(宿主提供的连续安全预算)`。本模块不提供预算算法，不使用“容量=无限”默认，也不修改SprintLegIK。预算未实现则取0，并标记组合未完成；不应把未使用的高度请求写成已完成的执行。

双腿目标必须继续取覆盖前的新鲜EMM足位和旋转，按空间线当前已验收的顺序执行。基底需要用源姿态计算；若宿主在算上臂前降低了hips，髋到头轴可能变化，应保存源身体基底或复核此偏差，不能宣称组合与手臂消融完全相同。首轮lowerBody=0没有该问题。

## 观察信号与验收队列

保留ObservedExpansion原公式和阈值。候选修改的是最终渲染几何，会改变观测分布；AppliedArmAngle字段语义也改变。增加新遥测或明确列头版本，不能混写进旧统计后直接比较。记录raw/final左肘展开、右臂角、候选有效/回退、高度请求/实际执行、脚误差、膝连续性和身体附近手腕/网格。

依次：0) 关闭候选回归原版本；1) 同源运动、lowerBody=0、无互动的原运动/旧臂/新臂；2) 已认可腿策略下的高度组合；3) 固定空间版本开回应，先额外夹臂/头部关闭；4) 十人完整验收。当前离线证据不替代任何一项。

遇到新的脚膝跳变、手穿躯干、接触破坏或用户认为更怪，则关候选保留现版。未通过感知不可把新策略命名为“地位成功版”。
