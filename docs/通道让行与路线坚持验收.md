# 通道让行与路线坚持候选

用户反馈：lateral-candidate约6s的1M/8H相遇，M看起来持续逼近、H反而侧身和减速。逐帧记录确认约5.99s时M输入速度1、H0.35；M不是完全没有偏转，但让行责任的视觉表达不符合角色设计。

## v15改动与边界

独立StatusYield开关（默认false），CLI `--status-yield`，与LateralSteps分别记录在config/runtime-config。保持策略10的基础距离函数、绕路预算、观测校准prototype-elbow-v1、安全阈值/候选分级和速度上限1。测试两开关均开启；自动注意/邻人凝视未恢复，表达分支不改。

1. 原方向性通道代价中，同向权重a从`clamp((dot(candidate_heading,other_heading)+.2)/1.2,0,1)`变为`a'=.65+.35a`，原等待候选a=1保持1。该代价仍乘`q*max(0,raw_estimate-own_status)`，仍在0.6/1.2/1.8s三个预测时刻评估前方偏重的空间场。变化是交叉/迎面相遇也可触发提前让路；对方速度<.25m/s仍关闭此方向场。它不是对方路径/目标读取，不赋予H绝对路权。
2. 原规划目标代价乘`1+1.5*own_status²`，L/M/H分别1/1.375/2.5。原目标代价同时包含偏离目标方向与降低命令速度的代价，因此自身status越高越坚持路线/速度。仍先按安全可行性与连续性分级，再比较代价；未削弱碰撞危险项，也未删除H对外显较低status的距离偏好。

这两个系数为本项目角色设计参数，没有科学标定或普遍人类行为结论。H需要避碰时仍能侧步、减速，M也不必每次停下；期望是更早消解冲突并让H少承担主动退让，而非制造一方永远直走的硬规则。旧status-gap-budget-v1基础距离model名称保留，扩展由statusYield=true和v15源码单独标识；旧通道exposure与新exposure语义不同，不直接当作同量比较。

侧步状态阈值未改，所有人物仍使用v14相同入口。空间函数先决定方向/速度，侧步执行这一结果。源动画、运动匹配查询/权重、膝部稳定和第三方代码均不改。

## 工程验证

在原自检中加入交叉输入对照，验证非同向输入的通道代价增加，且无观测权重时仍为0。priority-probe前14s和priority-candidate完整35s，seed806，策略10、Expression mode、response pose关闭、单程离场、60Hz诊断、30fps录像，近景跟随8H。对照上一完整lateral-candidate；新旧源码和compiled hash各自保留，不把旧录像重标v15。

`audit_unity_priority.py`同时报告固定4～8s与双方距离<2m窗口，避免只挑某个单帧；输入速度不是实际动画根速度，窗口也会随反馈变化。中心距离不能当作网格净空。检查完整到达/退出、膝部差分、日志、源码镜像和近景。

前14s初步结果：1M/8H最近中心距0.883→1.043m；固定4～8s的H平均命令速度0.743→0.906，平均目标偏角28.39→15.18°，低速(<.5)命令累计0.783→0s；M在新版同窗口平均命令速度0.846、平均偏角21.70°、低速命令0.517s。不能据此声称M全程更慢或每次都让行。
