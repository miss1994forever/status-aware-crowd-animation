# IE05 宿主适配契约（整合前草案）

基于已冻结 IE05，尚未接入或在Unity验证。空间线仍可修改；用户确认满意后按最新源码适配。这里的字段是接口约定，不冒充已实现代码。

## 数据和职责

| 输入 | 单位/来源 | 用途 |
|---|---|---|
| ownStatus | 本角色0–1设定；保持不变 | 个人表达基底与回应幅度 |
| rootSpeed | 控制器根节点实际水平位移/dt，m/s | 表达速度调节；不用期望速度或降髋位移 |
| bodyScale | 原始参考姿态的固定尺度，m | 高度请求归一化；不按每帧变形重新计算 |
| dt | 本轮模拟步长，秒 | 所有滤波/限速每帧仅推进一次 |
| rawPose | EMM已重定向且完成其接触处理的新鲜姿态 | 作为本轮修改基底，禁止在上轮结果上累加 |
| visibleSnapshot | 上一轮各活跃角色的最终骨骼E/H、世界根位置、实测水平速度、ID、有效性 | 空间与身体回应共用相同时间点；不包含邻人status/目标 |
| expressionMode | 原版、常规、加强、加强+躯干、加强+躯干+头颈 | 用户待选，不默认最大模式 |

输出：个人基底、期望/有效临时偏移、紧缩目标、请求/实际降髋、实际双臂角、躯干/头颈角、约束回退、最终E/H、脚目标误差。空间控制器独占根运动；表达层不改变导航目标或位移命令。

## 骨骼适配

| 源语义 | Unity Humanoid目标 | 缺失处理 |
|---|---|---|
| Hips | Hips | 关闭候选并记录原因 |
| Spine/Chest | Spine/Chest | 躯干通道不执行，不能用任意骨头替代 |
| 可选胸段 | UpperChest | 可选；若重分配角度，作为新适配配置单独记录并验证，不宣称与离线完全一致 |
| Neck/Head | Neck/Head | 缺Neck时默认禁用新增头颈通道，保留原动作 |
| UpperArm/LowerArm L/R | Left/Right UpperArm、LowerArm | 双臂候选要求完整；否则回到明确的原版路径 |
| UpperLeg/LowerLeg/Foot L/R | Left/Right UpperLeg、LowerLeg、Foot | 使用空间线最新SprintLegIK；禁止reference覆盖 |

原动作手腕、手指、脚旋转跟随源骨架。骨点版对子树旋转必须转成关节旋转，不能用世界位置逐点赋值破坏蒙皮骨长。身体基底从修改前姿态获取，左右/前方符号须用角色实际姿态验证。

## 每帧执行顺序

1. Director读取统一的上一帧可见快照；完成空间规划与身体表达目标计算。
2. EMM更新根运动、搜索与重定向，保留其原接触机制。
3. Actor回调保存新鲜源姿态、源脚目标、原脚旋转和当前Hint副本。
4. 用本角色状态推进一次ExpressionPolicy。组合搜索评估不同高度/手臂目标时，每次从同一源姿态与Hint副本开始；不让搜索过程推进全局滤波。
5. 只提交选定方案的腿Hint和关节姿态；依次应用腿约束、手臂、躯干/头颈。实际顺序与离线版本不同必须记录并做对照。
6. 采样最终E/H和误差供下一帧读取。离场对象跳过，清空对应即时滤波；不同角色不得共享可变策略实例。

## 必须去掉的重复效果

启用新表达时，旧的12*c+8*response内收与固定降髋不再执行。关闭新表达则精确回到冻结空间版原逻辑。旧IE02“response非零退回旧臂”的门控不适用于本次完整IE05接入。头颈俯仰只表达姿态，不重新加入已暂缓的目标注视。

## 观测标定

E公式兼容，但改变最终姿态会改变其分布。空间prototype-elbow-v1的.01/.16与IE05的参考中位数/尺度不得混用。IE05参考来自Bandai两个片段，不直接充当Unity参考。先记录原版与候选在相同运动输入下的E/H范围、饱和率；如需新标定，使用无标签的参考几何并单独标记配置版本。不得用真实邻人status反填在线估计。

## 验收顺序

- 关闭候选回归空间最终版，确认控制/结果未意外改变。
- 固定运动输入：原表达、新个人表达；看正侧近景和脚膝，记录姿态门控、回退、关节误差。
- 真邻居输入：加身体回应，检查有效偏移、无邻人释放、重复ID、退出清理和端点饱和。
- 十人闭环：同起点/目标/配置，检查到达、停滞、间距代理、额外路程、帧时和感知。中心距离不等于网格不穿插。

通过源码/数值检查不自动构成自然度或status验收。任何新膝跳变、碰撞或明显怪异姿态均可关闭候选回到原版；记录失败，不抹去对照。
