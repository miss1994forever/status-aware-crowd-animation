# 绕行收尾与短暂停让候选

用户要求不引入RVO，继续优化3L最后的多余绕行；提出L可等H通过再直达，并确认保留既有绕行/侧身策略。本轮沿用v15空间函数与原运动匹配，保留所有移动候选，不加入L遇H必停的规则。

## v16评分补充

独立RouteRecovery默认关闭，CLI `--route-recovery`，config/runtime-config分别记录。测试策略10、StatusYield/LateralSteps/RouteRecovery均开启，其余种子806、60Hz、Expression mode、response pose关闭、单程退出、30fps录像与上一版一致；近景跟随3L。

复用旧绕路预算权重w（越绕越小，最低.15），给候选v新增代价：

`J_recover = 2(1-w) max(0, |v| - dot(v, goal_direction))`

因此直接向目标前进和等待的新增代价均0；横移和背离目标在绕路积累后更贵。预算满时新增项为0，原status距离/通道偏好、群体避让仍生效。对原flow且crowdAversion>0的低status角色，原停顿项另减`.5(1-w)(1-speed)^2`；原停顿系数.8，所以该项仍非负，只是允许已绕远时短等优于继续退远。没有改变候选安全分级、危险代价、距离阈值、速度上限、侧步状态或侧向保持/释放程序；由评分选择短等、慢行斜步、继续绕行或回归目标。

角色只用自身路程、目标与已有公开几何/外显观测。没有读H隐藏status或目标，没有检测别人的到达标签来让其消失，也没有设定3L专用时间/路线。新项是项目设计假设，不是普遍行为规律或有保证的最短路算法。

## 验证

自检验证正向候选新增代价0、预算满时新增代价0、退行比横移代价高；实际运行recovery-probe 22s与recovery-candidate 35s，同源码，镜像保存。与priority-candidate v15对照，保留各自source/compiled哈希。评估3L首程距离、到达、退行命令、零速/慢速命令及实际静止；完整十人到达离场、中心距、1M/8H关系、膝部与日志。

这里零速或慢速命令不自动等于“有意识地等H通过”。只有实际轨迹与相遇时序吻合才能这样解释；若短斜步比等待更有效，也允许它继续走。没有实现显式估计H通行时间的等待状态机，这是后续可选扩展。
