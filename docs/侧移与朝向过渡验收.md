# 侧移与朝向过渡候选

用户指出budget新版3L旋转转身别扭，希望侧身/斜向步代替部分整身转向。先固定空间策略10与速度上限1，不新增或下载动作。

## 可用接口与素材

现用MMData为EnvironmentAgentsMMData，包含AnimationData/emm/strafe.asset（guid 2f20d8c06f8203d4b9a8d39c86fab6bd）。原CrowdCharacterController.SetMovementDirection同时写InputMovement和DesiredRotation，默认身体跟随移动方向；原SwapFixOrientation接口可冻结已有DesiredRotation而继续更新位置输入，且FutureDirection查询和旋转预测均使用该DesiredRotation。PoseSet根朝向来自hips朝向，不是恒按速度生成，因此该数据库可以表达非正向行进。

## 第一候选：受限原生朝向保持

新增SprintSideStep状态只调用原生SwapFixOrientation，不改第三方代码、不硬转骨骼、不调整动作播放速度。独立LateralSteps开关默认false；自动测试都保持Expression mode、额外回应pose关闭、稳定膝部与单程退出。

运行超过1s，附近活跃人物距离<2.2m、命令速度>=0.69、相对自己目标偏转15～70°、当前控制朝向与命令夹角<=35°时，允许保持已有目标朝向最多0.55s。保持期间若夹角>50°、速度<0.3、邻人不再靠近或超时，恢复跟随移动方向，并冷却0.7s。到达原目标时主动释放。不是主动看邻人，也不读邻人的隐藏status或目的地。

这里保持的是原生DesiredRotation（上一个运动朝向目标），不是任意指定的新朝向；当前控制器和实际动画根仍通过原弹簧/惯性化过渡。新候选能否实际选择斜步素材，必须读motion.csv和看近景，不能仅凭持有标志宣称已经侧身。所有原空间候选与安全检查不改，但朝向改变会影响MM动画选择和实际轨迹，因此会反馈影响后续空间规划和ObservedExpansion；未重定义身体观察信号或静默重校准。

## 验证设置

同一源码顺序运行sidestep-baseline（lateralSteps=false）与sidestep-candidate（true），各35模拟秒、60Hz、录像30fps、近景跟随3L。新增motion.csv在10000执行序逐帧记录实际MM根位置、输入、控制朝向、模拟根朝向、保持状态、所选clip索引/名称/源帧。保留逐帧knees.csv。

工程自检包括进入、有限时长与冷却、过大朝向差释放。关键对照包括3L在8～14秒的根朝向变化、首程实际斜向行走比例、是否真的选中strafe、到达/离场、近距并行、膝部与资源。不能将动画clip选择率或朝向平滑当作人类感知自然性通过。

## 第二候选：放宽慢速侧步入口（social-space-v14）

用户同意先尝试加入侧步。仍用原生SwapFixOrientation与原MMData，不改上游控制器、查询权重、空间函数、安全距离或速度上限。先消除第一候选对慢速侧向动作的限制：

- 进入速度从>=0.69改为>=0.34，覆盖规划器0.35/0.7/1三个移动档；源strafe片段的侧向样本平均速度约0.63m/s，仅作为素材范围说明。
- 目标方向偏差20～85°、当前控制朝向与输入夹角<=70°时允许保持；超过85°或速度<0.25时释放，避免持续倒走。
- 单次保持最长0.85s，冷却仍0.7s；邻人离开2.2m范围、到达目标、关闭开关时均释放。
- 入口对所有人物相同，status仍仅通过原空间偏好影响运动候选。没有主动注视、没有快步或播放加速；横移方向和速度仍由原规划器决定。

这仍是有条件的短朝向保持，不保证每次请求都选中strafe，也不按名字强制切片。实际是否侧步以源根局部速度、实际根行进方向和连续近景共同评估。允许更大角度后可能影响实际间距与反馈规划，需要完整十人验证。

运行顺序：lateral-probe 14s先检查编译、源动作与近距；同源码lateral-candidate完整35s、种子806、策略10、60Hz、近景3L、录像30fps。与sidestep-baseline（原预算策略）及sidestep-candidate（第一候选）区分记录；v14只改侧步状态阈值与对应自检/marker，旧录像保留原版本。
