# 候选项目对照

本页记录用于帮助选题的代表项目。目的不是直接选择一个项目复现，而是观察各方向已经解决了什么、忽略了什么，以及哪些技术适合当前设备和课程规模。

## 建议观看顺序

1. JuPedSim Web：先观察传统行人模拟能表达什么；
2. PySocialForce / Adding Sociality：观察加入社会群组后产生的变化；
3. Environment-aware Motion Matching：观察轨迹和全身动作结合后的视觉提升；
4. Disney Generate-and-Rank：观察自动化怎样服务创作者；
5. InterGen：观察生成式双人动作的能力和边界。

## 方向一：情境压力与局部协商

### JuPedSim Web

- 入口：https://app.jupedsim.org/
- 开源的行人动力学系统；首页的单房间疏散、双向通道和瓶颈等卡片目前只是图片与场景说明，并非可点击运行的示例；
- 进入实际编辑器需要点击 “Start your own”，目前会要求通过 Helmholtz ID 登录；
- 强项是轨迹、密度、通行效率和标准测试；
- 适合作为“传统模拟能做到什么”的参照；
- 局限是人物主要表现为运动粒子，无法直接表达细致的身体反应和人物关系。

### Vadere

- 入口：https://www.vadere.org/
- 开源的微观行人和人群模拟框架；
- 已实现 Social Force、Optimal Steps 等运动模型，并包含心理层；
- 社会身份与行为变化示例：https://www.vadere.org/applications/social-identity-and-behavioral-changes/
- 可以参考其 threat、cooperation 和 locomotion 分层方式；
- 框架偏科学仿真，若直接用于课程演示，视觉动画需要另做。

### 这一方向的可研究空隙

- 不是再做一个普通疏散模拟；
- 可以比较不同压力条件下局部互动策略的可见性和群体结果；
- 可以研究“中等压力是否比低压力和极高压力产生更明显的行为异质性”；
- 需要避免把竞争、恐慌、人格和社会地位混为一谈。

## 方向二：关系图驱动的小群组

### PySocialForce

- 代码：https://github.com/yuxiang-gao/PySocialForce
- 基于 NumPy 的扩展 Social Force 实现，MIT License；
- 支持个体、障碍物和社会群组；
- 群组机制包含 coherence、repulsion 和 gaze 等力；
- 能直接输出动画，安装和修改成本较低；
- 适合作为算法原型或对照基线。

### Adding Sociality to Virtual Pedestrian Groups

- 论文：https://webspace.science.uu.nl/~gerae101/pdf/Adding_Sociality_to_Virtual_Pedestrian_Groups_VRST2015.pdf
- 让 2—4 人小组保持可交流的空间结构；
- 小组遇到障碍时能够暂时分裂，之后重新组织；
- 可扩展到大量角色；
- 但群组成员关系基本预先给定，重点是保持队形和连贯性，而不是生成新的社会关系。

### 这一方向的可研究空隙

- 现有轻量模型常把群组关系设为固定标签；
- 可以研究关系强度、共同目标和局部主导/退让如何共同影响队形；
- 可以让群组在不同空间和拥挤条件下出现等待、分裂、重组和领导者变化；
- 不一定要让陌生人凭空成为朋友，社会关系可以是创作者输入。

## 方向三：可导演的少量人物互动

### Disney Generate-and-Rank

- 项目页与演示：https://studios.disneyresearch.com/2014/11/19/generating-and-ranking-diverse-multi-character-interactions/
- 根据高层描述和动作捕捉数据库生成大量多人互动候选；
- 系统对候选进行排序，再交给创作者选择和修改；
- 展示场景主要是多人格斗；
- 重要启发是：自动化不需要输出唯一“正确答案”，可以向导演提供少量高质量且多样的候选。

### Event-Centric Crowd Authoring

- 项目页：https://studios.disneyresearch.com/2016/10/19/an-event-centric-approach-to-authoring-stories-in-crowds/
- 创作者通过事件控制主要角色和人群；
- 系统适合故事板和预演，并允许从人群中提升重要角色的行为精度；
- 体现了主要角色、次要角色和背景人群可以使用不同控制层级。

### Environment-aware Motion Matching

- 演示：https://upc-virvig.github.io/Environment-aware-Motion-Matching/
- 代码：https://github.com/UPC-ViRVIG/Environment-aware-Motion-Matching
- SIGGRAPH Asia 2025，实时结合身体姿态、根轨迹、障碍物和其他 agent；
- 演示包括狭窄通道侧身、不同速度人物相遇、躲避车辆、跳跃、下蹲和风格适配；
- 官方仓库包含 Unity 6.2 项目、无第三方资产即可运行的场景，以及所需动作数据；
- 不要求 CUDA，比深度生成模型更适合 M2 设备；
- 它主要解决环境适应和碰撞，不直接建模复杂社会关系，因此可以作为动画表现层而不是完整研究问题。

### InterGen

- 演示：https://tr3e.github.io/intergen-page/
- 代码：https://github.com/tr3e/InterGen
- 能根据文本生成拥抱、争吵、格斗、鞠躬等同步双人骨骼动作；
- 提供 InterHuman 数据集和官方实现；
- 官方运行环境要求 Ubuntu 和 CUDA GPU，训练和完整复现不适合当前 M2 设备；
- 可用于了解当前生成质量和研究评价方式，不建议直接作为课程项目的核心依赖。

## 初步工程判断

| 技术/项目 | 本机可行性 | 适合作为基线 | 视觉表现 | 主要风险 |
|---|---:|---:|---:|---|
| JuPedSim Web | 高 | 高 | 低 | 偏工程/安全仿真 |
| Vadere | 中高 | 高 | 低 | 框架较大、视觉较弱 |
| PySocialForce | 高 | 很高 | 低到中 | 需要自己增加研究机制与 3D 表现 |
| Environment-aware Motion Matching | 中高 | 中 | 很高 | 系统复杂，修改前需理解 Motion Matching |
| Disney Generate-and-Rank | 不明确 | 低 | 高 | 无现成完整代码和动作数据库 |
| InterGen | 低 | 低 | 很高 | CUDA、数据和深度模型成本 |

## 暂时最现实的组合方式

如果未来选择中小型群组方向，可以把系统分为两层：

1. 轻量的互动/关系层，负责目标、群组、局部协商和轨迹；
2. Unity 中的动作表现层，负责把轨迹决策转成角色姿态和动作。

研究贡献更可能位于第一层；第二层用于让差异在视觉上真正可见。两层不必一开始同时完成，先用简单几何角色验证机制，再升级为骨骼动画，可以降低项目风险。
