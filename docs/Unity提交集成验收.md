# Unity 提交集成验收（2026-11-04）

用户转述助教明确允许 Unity 自主算法以及复用开源 EMM 的基础行走和衔接。主提交改为 Unity + EMM；Python 保留实验分析，不再维护另一套完整演示。

## 模块与机制

源码权威副本：`src/unity_submission`；复制到 Unity 的 `Assets/SubmissionSprint`。独立场景 `SubmissionDemo.unity`，不覆盖官方场景和包代码。

- EMM：动作库搜索、环境适应行走、骨骼重定向与原有惯性衔接。
- SprintActor：重定向后改变髋部高度、单侧上臂形态与注意朝向；两段式腿部 IK 尽量保留该帧 EMM 原始脚踝位置和脚旋转。没有新增接触锁定，不能据此宣称解决滑脚。
- SprintDirector：10 人相向通行。先快照所有位置、速度与上一帧可见肘部展开，再预测邻人的最近接近时间及距离，选择当前最相关对象，平滑调整注意和配合强度。

角色不读取他人的隐藏 status。观察量是可见肘部展开/肩宽；其到“估计”的线性映射尚未校准，仅是几何代理。自己的隐藏参数影响收缩基底及配合权重。当前不会存储跨相遇关系。

身体收缩幅度采用先前打招呼实验候选：最大降低 2.06 cm，上臂最大内收 12°，互动另增加最多 8°。这只是跨动作接入假设，打招呼实验的单用户反馈不意味着它适用于行走，也不意味着高低地位已验证。此版本的完整性优先于添加未经验证的新参数。

## 模式

0. Baseline：EMM 与所有模式共用的几何避让支持。
1. Expression：加入自己的身体表达。
2. Response：再加入可见身体观察、预测相遇、注意与即时回应。

各模式使用相同起点、目标、人数、角色和种子；实时帧步长未锁定，不能保证逐帧相同。界面实时切换仅用于诊断。观感比较应使用分别重新启动的运行。

## 启动

打开现有 EMM Unity 工程中的 `Assets/SubmissionSprint/SubmissionDemo.unity` 后 Play。Baseline / Expression / Response 切换模式；Close view 和 Next actor 切换近景。默认手动运行不自动结束。

自动验收：向 `outputs/unity-submission/run.request` 写 JSON，例如 `{"run":"new-unique-run","mode":2}`。已打开该工程的编辑器会运行 35 秒并停止；目录已存在时拒绝覆盖。输出 telemetry.csv、三张截图和 finished.txt；finished 仅代表时长结束，不代表成功。

用 `python3 scripts/audit_unity_submission.py outputs/unity-submission/运行名` 生成统计。检查日志异常和视觉结果后，才能判定运行是否有效。
